# Design Patterns Glossary

- **Abstraction:** A contract or model that exposes relevant behavior while hiding implementation detail.
- **Adapter:** A wrapper that translates one interface into another.
- **Cohesion:** How closely related the responsibilities within a component are.
- **Command:** An object or value representing an operation to be invoked or queued.
- **Composition:** Building behavior by combining collaborating components.
- **Coupling:** The degree to which components depend on one another.
- **Decorator:** A wrapper that adds behavior while preserving an object's interface.
- **Dependency injection:** Supplying dependencies from outside a component.
- **Facade:** A focused interface that simplifies access to a subsystem.
- **Factory Method:** A creation pattern in which subclasses or overriding methods determine the product.
- **Idempotency:** A property where repeating an operation has the same intended effect as doing it once.
- **Mediator:** An object that coordinates interactions among collaborators.
- **Observer:** A pattern where a subject notifies registered observers of changes.
- **Proxy:** A stand-in that mediates access to another object or resource.
- **Repository:** An application/data-access abstraction for retrieving and persisting domain objects.
- **Strategy:** An interchangeable implementation of an algorithm.
- **Unit of Work:** A pattern for tracking changes that should be committed together.
- **Visitor:** A pattern for adding operations across a stable set of element types.
