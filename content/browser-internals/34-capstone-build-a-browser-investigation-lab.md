# Capstone: Build a Browser Investigation Lab

> DevsLibrary · Browser Internals · Lesson 34

## Objective
Investigate one real browser behavior and produce evidence-based documentation that distinguishes application code, standards behavior, and engine implementation.

## Choose a topic
Examples include script scheduling, caching, layout thrashing, image loading, service worker updates, storage restrictions, cross-origin requests, accessibility-tree semantics, or browser memory behavior.

## Investigation plan
1. Write a question that can be tested.
2. State a hypothesis and expected outcomes.
3. Create a minimal reproducible page or application.
4. Identify relevant official documentation or specification sections.
5. Test at least two environments when possible.
6. Capture traces, console output, network evidence, or accessibility-tree output.
7. Separate observations from explanations.
8. Make one change and repeat the experiment.
9. Document limits and remaining uncertainty.

## Deliverables
- Question and hypothesis.
- Reproduction steps and source code.
- Environment matrix.
- Evidence and measurements.
- Specification or official documentation references.
- Findings, alternative explanations, and limits.
- A practical engineering recommendation.

## Evaluation rubric
A strong investigation is reproducible, uses measurements that match the question, avoids overgeneralizing from one browser, distinguishes standard requirements from implementation details, and communicates uncertainty honestly.

## Extension
Turn the investigation into a regression test or a short internal guide for your team.
