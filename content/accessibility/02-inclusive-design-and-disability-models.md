# Inclusive Design and Disability Models

> DevsLibrary · Web Accessibility · Lesson 02

## From user deficit to barrier removal
The medical model tends to locate disability in an individual's condition. The social model emphasizes that environments, systems, and attitudes create disabling barriers. In practical web work, a useful question is not “What is wrong with this user?” but “Which choices in this product prevent this person from completing the task?”

The interaction between a person and an interface is contextual. A complex multi-step checkout can burden a user with memory difficulties; a tiny target can burden a person with tremor; an unlabeled icon can burden a screen-reader user; audio-only instructions can exclude a deaf user.

## Inclusive design is a process
Inclusive design deliberately considers variation in ability, language, culture, context, device, and preference. It does not mean one interface must satisfy every possible need in exactly the same way. It means avoid unnecessary barriers, support personalization where feasible, and provide equivalent ways to complete important tasks.

Useful practices:
- Include disabled participants in research and usability testing.
- Ask about access needs without requiring users to disclose diagnoses.
- Avoid designing only for an imagined “average” user.
- Support preferences such as reduced motion, larger text, and high contrast.
- Make error prevention and recovery part of the experience.

## Avoid common mistakes
Do not treat accessibility as a charity feature, equate disability with inability, or rely on a single “accessible mode” to repair an inaccessible default experience. Do not presume that automated compliance guarantees a good experience.

## Exercise
Run a short design review of a page you know. Identify three assumptions the page makes about vision, hearing, motor control, cognition, or context. Rewrite each assumption as a testable design question.
