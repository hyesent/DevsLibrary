# Accessible Content, Help, and Documentation

> DevsLibrary · Web Accessibility · Lesson 32

## Content is part of the interface
Use meaningful headings, descriptive link text, clear instructions, accessible tables, and alternatives for images and media. A technically accessible component can still create a barrier if its text is ambiguous, inconsistent, or unnecessarily complex.

## Help should be findable
Put instructions where users need them and make them available before an irreversible action. Keep support paths consistent. Avoid instructions that depend only on shape, color, location, or sound, such as “press the green button on the right” without naming the button.

## Accessible documents
PDFs and office documents may require tagged structure, reading order, document language, meaningful links, alt text, table headers, and selectable text. A scanned image of a document is not automatically accessible. When feasible, publish a well-structured HTML version as well as downloadable files.

## Translation and localization
Accessibility should survive localization. Text expansion can break fixed layouts; translated strings can change meaning; date, number, and address formats vary. Mark language appropriately and test localized forms and error messages. Do not assume automated translation preserves clarity or accessible naming.

## Exercise
Review a help article and its downloadable document. Check heading structure, link text, images, tables, language, reading order, and whether instructions remain understandable without visual positioning cues.
