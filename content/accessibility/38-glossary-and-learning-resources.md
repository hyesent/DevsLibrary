# Glossary and Further Learning

> DevsLibrary · Web Accessibility · Lesson 38

## Glossary
- **Accessible name:** The programmatic name of a control or interface object.
- **Accessibility tree:** The browser's representation of interface semantics exposed to assistive technology.
- **Assistive technology:** Hardware or software that helps people perceive or operate digital content.
- **Conformance:** Meeting all applicable requirements of a specified standard and level within a defined scope.
- **Focus:** The interface location that currently receives keyboard input.
- **Landmark:** A semantic region that supports navigation, such as main content or navigation.
- **Live region:** A region whose updates can be announced without moving focus.
- **POUR:** Perceivable, Operable, Understandable, Robust.
- **Screen reader:** Assistive software that presents interface information through speech, Braille, or both.
- **Semantic HTML:** HTML elements chosen for their meaning and built-in behavior.
- **Text alternative:** Text that communicates information or function represented by non-text content.
- **WCAG:** Web Content Accessibility Guidelines, a technical standard for web accessibility.

## Authoritative learning resources
Use the latest official material when checking requirements or implementation details:
- W3C Web Content Accessibility Guidelines (WCAG): https://www.w3.org/WAI/standards-guidelines/wcag/
- W3C WAI tutorials: https://www.w3.org/WAI/tutorials/
- WAI-ARIA Authoring Practices Guide: https://www.w3.org/WAI/ARIA/apg/
- W3C Understanding WCAG: https://www.w3.org/WAI/WCAG22/Understanding/
- MDN accessibility learning resources: https://developer.mozilla.org/en-US/docs/Web/Accessibility
- WebAIM articles and tools: https://webaim.org/

## How to keep learning
Pick a real task, inspect its semantics, test it with keyboard, review its visual states, and verify it with assistive technology. Standards and browser behavior evolve; revisit the official documentation and test with the environments your users actually use.

## Final reflection
Write down three accessibility practices you will apply to every feature, two testing habits you will add to your workflow, and one assumption you will stop making about users.
